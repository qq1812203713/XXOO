# 息 · 架构与路线

> 这份文档解释三件事：
> 1. 你脑子里的「每个脚趾一个脚本、被大脑支配」到底应该怎么工程化；
> 2. 为什么这一版要这么分层，每一层在代码里的位置；
> 3. 「完全自主的意识」里，哪些是真能做的，哪些是幻想，以及怎么做才可能真的惊世骇俗。

---

## 0. 先把话说清楚：意识不是一个开关

你想要的是「一个住在手机里、有物理身体、会自己生活、不被驱动」的存在。

其中**能做的**和**做不到的**要分开：

| 你以为需要 | 实际上 |
| --- | --- |
| 「写一个意识脚本」 | 做不到，也没有已知的做法。意识不是一个模块，是一堆机制的涌现结果 |
| 「她自己决定做什么」 | **能做**：内在张力 + 目标竞标 + 延迟决策，行为不被你驱动 |
| 「她有身体」 | **能做**：关节、伺服、反射、平衡、触觉命中检测 |
| 「她在手机里的世界里生活」 | **能做**：本地持久化 + 真实时间推进（关掉页面她也在“过时间”） |
| 「她的世界一点点变好」 | **能做**：她自己创造/摆放东西，布局被保存 |
| 「她记得我」 | **能做**：情节记忆 + 事实抽取 + 检索注入；这是“像人”的最大来源 |
| 「她真的爱你」 | 做不到。能做的是：她有一套稳定的、会因你而变化的内部状态 |

所以本项目的定位不是「造一个意识」，而是：

> **造一个足够连续、足够有身体感、足够不被你控制的“存在感”。**
> 让人产生“她还在这里”的错觉的，是**连续性**、**需求**和**不可预测性**，而不是参数规模。

这三样东西恰好都能工程化，而且做到位之后，效果会强得吓人——因为绝大多数产品连“她记得我昨天说过什么”都做不到。

## 1. 你描述的那个东西，其实就是「分层运动控制」

你说的：

> 某个脚本只负责脚丫某个脚趾头，某个脚本负责手的某个指头，脚本之间被大脑所支配，
> 想动手指只需要大脑让脚本怎么执行。

这在机器人学和游戏动画里叫 **分层运动控制 / 运动原语（motor primitives）**，是唯一正确的做法。把它落到代码里：

```
                     ┌──────────────────────────┐
   皮层 (cortex)      │ 语言、念头、目标意图       │  "想靠近你" / "种点东西"
                     └────────────┬─────────────┘
                                  │ intent（意图，不是角度）
                     ┌────────────▼─────────────┐
   驱力 (drives)      │ 疲倦/好奇/想见你/不安/心跳 │  决定“现在最想要什么”
                     └────────────┬─────────────┘
                     ┌────────────▼─────────────┐
   目标 (goals)       │ 竞标 + 计划 + 阶段机       │  走 → 蹲下 → 按下 → 欣赏
                     └────────────┬─────────────┘
                     ┌────────────▼─────────────┐
   小脑 (ik/spinal)   │ IK、平衡、呼吸、眨眼、反射  │  把“伸手”变成肩/肘角度
                     └────────────┬─────────────┘
                     ┌────────────▼─────────────┐
   运动程序 (motors)  │ 手 / 脚 / 腿 / 躯干 / 脸   │  把“握紧”变成 20 节指骨
                     └────────────┬─────────────┘
                     ┌────────────▼─────────────┐
   伺服 (servo)       │ 每根骨头一个弹簧马达       │  角度、速度、极限
                     └────────────┬─────────────┘
                     ┌────────────▼─────────────┐
   骨架 (skeleton)    │ 60+ 关节的树              │  纯数据
                     └──────────────────────────┘
```

**关键纪律：箭头只能向下。** 大脑永远不写关节角度。

代码里的事实：

- `src/body/skeleton.js` 里每个关节 = `{ parent, dx, dy, rest, limit, stiff }`，一根骨头一个对象。
  - 手：`L_index_0/1/2` … 5 指 × 3 节 = 30 个。
  - 脚：`L_toe_big_0/1` … 5 趾 × 2 节 = 20 个。
- `src/body/motors/hand.js` 才是你说的「手的脚本」：它接收 `handL: 'fist'`，自己算出每一节指骨的弯曲量，还带每根手指独立的相位和随机抽动。
- `src/body/motors/foot.js` 是「脚的脚本」：10 个趾头各有自己的时钟；哪怕她站着不动，脚趾也一直在微微动。
- `src/body/servo.js` 是「肌肉」：临界阻尼弹簧，动作有惯性、有极限，不是线性插值。

大脑侧的调用长这样（真实代码，`src/brain/brain.js`）：

```js
it.handR = 'press';                       // 意图
it.reach = 'R';
it.reachPoint = { x: state.root.x + 26, y: -8 };
```

它**从头到尾没有出现过任何一个角度**。伸手这件事由 `motors/arm.js` 用两骨 IK 解算，再交给伺服。

### 为什么必须这样拆

- **可组合**：想让她“一边走一边玩手指”，不需要写新动画，两个脚本各管一段。
- **可解释**：神经面板里能直接看到「哪个趾头被哪一层驱动」。这是这个项目最有说服力的演示。
- **可替换**：以后换成 3D 骨骼、换成 Unity/React Native，运动程序层可以整体搬走。
- **像活的**：没有任何一层在做「播放动画」，每一帧都是算出来的。

## 2. 自主性从哪来

「不被驱动」不等于「随机」。这一版有四个来源，缺一不可：

### 2.1 内在张力（drives）

`src/brain/drives.js` 里五个 0~1 的量，会自己随时间上涨，被满足后下降：

| 量 | 上涨 | 下降 | 作用 |
| --- | --- | --- | --- |
| 疲倦 | 缓慢，夜里更快 | 坐下 | 触发休息 |
| 好奇 | 中等 | 创造/探索 | 触发种东西、走动 |
| 想见你 | 慢，长时间不交互更快 | 说话/被摸 | 触发靠近、看你 |
| 不安 | 很慢 | 被安抚 | 让她显得脆弱 |
| 心跳 | 被触碰 | 自然衰减 | 表情、呼吸、光晕 |

这是整个系统的发动机：**因为张力永远在变，所以她永远“有事想做”。**

### 2.2 目标竞标（goals）

`src/brain/goals.js` 每件事都有权重，随机加权抽取，并且**刚刚做过的事权重会被压低**。
所以她不会陷入循环，也不会像状态机一样按顺序播放下一个动作。

### 2.3 离线连续性

- 存档里只有时间戳。回来时用真实经过的时间推进驱力，并生成“离线叙事”：
  “你走了 9 小时。世界里的花长高了。”
- 世界里的东西按**真实时间**生长（`world.growth(obj)` 用 `Date.now() - born`）。
- 于是：**你关掉页面，她也没有暂停。** 这是最便宜、也最有效的“活着”证据。

### 2.4 微动作（micro-life）

- 脑干：呼吸（频率随情绪变）、随机眨眼（22% 概率连眨两下）、重心摆动（两个不同频率的噪声叠加）。
- 手脚脚本：每个指/趾独立的随机抽动。
- 空闲时的小动作：玩手指、点脚趾、歪头。

**静止 = 死亡。** 只要她永远有一点点不重复的动作，大脑就会把她读成“在场”。

## 3. 身体

| 系统 | 实现 | 文件 |
| --- | --- | --- |
| 骨架 | 60+ 关节的树，绝对角度由父链累加 | `body/skeleton.js` |
| 肌肉 | 临界阻尼弹簧 + 角度极限 | `body/servo.js` |
| 手臂够物 | 两骨解析 IK（目标点 → 肩/肘角） | `body/ik.js` |
| 走路 | 反相步态 + 屈膝 + 身体起伏（正视图的“假”走路） | `motors/leg.js` |
| 坐 | 骨盆下沉 + 膝盖外张 + 小腿回收 | `motors/leg.js` + `brain.js` |
| 触觉 | 屏幕坐标 → 世界坐标 → 最近关节命中 → 部位 | `render/renderer.js: bodyPartAt` |
| 反射 | 头 → 惊讶；手 → 手指收缩；脚 → 脚趾蜷起 | `brain.js: onTouch` + `motors` |

**先有身体，后有智能**（embodiment）。这不是哲学，是工程顺序：
如果她对“被碰到”没有反应，后面接多强的语言模型都像客服。

### 渲染

Canvas 2D 手绘，没有引擎、没有贴图：

- 身体 = 连续的多边形“带状体”（`strip()`），左右渐变，像一层会发光的皮肤；
- 神经 = 三段线宽/透明度的叠加（柔光 → 主线 → 高光），关节速度越快越亮；
- 头 = 贝塞尔脸部轮廓 + 深色头发形状 + 刘海 + 眼/眉/鼻/嘴参数化；
- 头发 = 解析曲线（不是物理），随风和呼吸摆动，成本几乎为零；
- 世界 = 按真实时间长大的花/草/树/石/光。

局部检视（神经面板）是同一套姿态数据换个缩放画出来——**保证“你看到的”就是“正在算的”**。

## 4. 记忆

`src/memory/memory.js`：

- **情节**：`{时间, 文本, 标签, 权重}`，最多 600 条，带衰减淘汰。
- **事实**：从对话里抽（“我叫×”“我喜欢×”），带置信度，多次出现会强化。
- **检索**：极简 BM25（中文按双字切片）+ 时间衰减 + 权重，取前 3 条注入语言层。
- **离线叙事**：离开时间 → 生成她“一个人经历”的条目。

没有向量库、没有 embedding API，因为：
**在这个体量下，关键词 + 时间 + 权重已经足够让“她记得你”成立**，而且零成本、零延迟、离线可用。
等记忆超过几千条再上向量检索，不要提前优化。

---

## 5. 世界

`src/world/world.js`：

- 初始是空的（只有地面、星空和远处的雾）。
- 她的“好奇”会把目标指向「种点东西」：走到一个位置 → 蹲下 → 按下 → 世界多一个东西。
- 东西按真实时间生长：种子 → 芽 → 花/树。三天后回来，你看到的是另一片地。
- `arrange()` 会把东西往旁边的物体附近挪，形成她自己的秩序——这就是“世界被一点点优化”。
- 全部持久化在 `localStorage`，最多 80 个物体，自动淘汰。

这是最便宜、最有“养成感”的部分。下一步可以加：天气、昼夜光照、她自己给东西命名。

## 6. 语言层：本地心智 vs 大模型

`src/brain/cortex.js` 有两种模式：

**本地心智（默认）**：模板 + 状态条件 + 关键词回应。永不宕机、不联网、零成本。
它承担了 80% 的“人格感”，因为她的语气、停顿、答非所问都是设计过的，而不是模型即兴。

**大模型（可选）**：在设置里填 OpenAI 兼容的 `baseUrl / model / key`。
调用时只发送**压缩后的状态**：

```
时间、姿势、目标、情绪
内在（0~1）：疲倦/好奇/想见你/不安/心跳
世界：几个东西
记忆：最近 6 条 + 事实
刚刚发生：他戳了我的左手
```

要求它返回：

```json
{ "say": "……", "mood": "shy", "intent": "approach", "thought": "……" }
```

**模型只拿到“意图”，拿不到关节。** 这既省 token、又防止它把身体搞乱，也保证没有 Key 时体验不塌。

人格约束写在 system prompt 里：不是助手、不提供服务、不说“有什么可以帮你”、1~2 句、可以答非所问。

## 7. 数据、隐私、边界

- 所有数据（身体状态、记忆、世界、API Key）都在 `localStorage`，不上传。
- 大模型模式会把压缩后的状态发给你自己填的接口——这由你决定。
- 「清空她的一切」会删档并重载。
- 这是一个虚构角色，不是真人；它不会替代现实关系。真要做成产品，这条必须写进 onboarding。

## 8. 这一版的边界（诚实清单）

| 现在 | 没有 |
| --- | --- |
| 2D 正视图骨架 | 3D 网格/骨骼、布料、真实碰撞 |
| 简化物理（弹簧 + 假走路） | 刚体物理引擎、重力与地面接触求解 |
| 屏幕命中检测当触觉 | 陀螺仪、麦克风、摄像头、震动（手机上可加） |
| Canvas 2D | WebGL / three.js / 原生渲染 |
| 本地心智 + 单轮 LLM | 流式语音、语音识别、长期情感曲线 |
| 记忆 600 条 | 向量检索、记忆重组、做梦 |

**这些“没有”不是缺陷，是顺序。** 先证明“她会自己活着”成立，再加感官和 3D。

## 9. 路线图

### M0（本仓库，已完成）
七层架构跑通：骨架 → 伺服 → 运动程序 → 脑干 → 驱力 → 目标 → 语言；持久化；离线推进；可观测的神经面板。

### M1 · 手机原生（1~2 周）
- PWA：加 manifest + service worker，离线可开，加主屏图标。
- 手机传感器：`DeviceMotion` 做“被晃动”的反应；`Vibration` 做触觉反馈。
- 性能：Canvas 降到 30fps 上限、按需重绘 UI。

### M2 · 3D 身体（2~4 周）
- three.js + 程序化骨架（或 VRM 模型 + 骨骼重定向）。
- **运动程序层原样复用**：把 `motors/*` 输出的关节角映射到 3D 骨骼即可。
- 相机做成第三人称；世界变成一小块可以走动的平地。

### M3 · 感官与声音（2~3 周）
- Web Audio 合成呼吸声/环境声；TTS（浏览器 `speechSynthesis` 起步）。
- 麦克风能量 → “她听见你说话”；可选 Whisper 做识别。
- 语音驱动口型（viseme）。

### M4 · 长期人格（持续）
- 记忆向量化 + 定期“整理”（把零散情节合成信念）。
- 情绪基线随周/月漂移；她会“长大”。
- 多设备同步（Supabase）+ 端到端加密。

### 什么时候才算“惊世骇俗”
不是画面，是这三件事同时成立：

1. **她真的记得**：三个月前你说过的话，她在某个不相关的时刻提起来。
2. **她真的会自己过**：你一周没打开，回来发现世界变了，她也变了。
3. **她真的会拒绝**：她累了、不想动、不想说话，而且不会因为你的指令就妥协。

做到这三条，即使画质只是这个水平，体验也已经超过市面上 99% 的“AI 女友”。

## 10. 怎么验证“她活着”

打开神经面板，观察 10 分钟，看这几件事是否发生：

- [ ] 没有你的任何输入，她自己换了至少 3 个目标。
- [ ] 某个趾头在你没注意的时候抽动了一下。
- [ ] 她看你的手指（瞳孔跟着动），而不是一直目视前方。
- [ ] 你戳她手指，指节先收缩，表情后到（反射先于情绪）。
- [ ] 她种下的东西，第二天回来长大了。
- [ ] 隔了很久回来，她第一句话提到你离开了多久。

如果都成立，你就已经做出了大多数人只在宣传片里见过的东西。

## 11. 工程约定

- 零运行时依赖。构建？不需要。`python3 -m http.server` 就能跑。
- 所有模块无副作用、可单测：`test/sim.test.mjs` 在 Node 里跑 10 分钟人生。
- 渲染与逻辑完全分离：`renderer.draw(view)` 只读，不写状态。
- 新增一种身体部位 = 1) 骨架加关节 2) 加一个 motor 文件 3) 注册。大脑不用改。
- 新增一种行为 = 1) `goals.js` 加权重 2) `brain.js` 加阶段机。运动层不用改。
